# 版本与兼容规则

版本只使用规范化的 `major.minor` 两段整数形式，例如 `1.0`。不接受前导零、补丁号、预发布标记或构建元数据，因为这些值会让跨仓消费边界变得含糊。

- 主版本必须精确匹配；主版本变化表示不兼容语义。
- 次版本只有在兼容矩阵声明后才能消费；新增语义必须通过 feature 表达。
- `requiredFeatures` 未被矩阵登记时拒绝，避免消费者静默降级。
- `optionalFeatures` 可被未知消费者忽略，但发布者不能把必需语义伪装成 optional。
- 已发布的 ID 不复用；摘要变化代表载荷内容变化，不能只改登记项中的摘要来绕过校验。

具体协议族的版本、feature 和兼容消费者由后续 Ticket 在 `compatibility/matrix.json` 中登记。P0-001 只提供格式和拒绝规则。
