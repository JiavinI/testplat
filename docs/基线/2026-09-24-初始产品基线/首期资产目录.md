# P0 首期资产目录

状态：初始产品基线派生索引；已随基线于 2026-09-24 确认。

## 1. YAML 资产种类

P0 只允许以下七类严格、版本化资产；每个 YAML 文件一个资产，使用 `apiVersion: testplat.io/v1`，同一测试项目内 `kind + metadata.id` 稳定且跨类型 ID 全局唯一：

| 资产 | P0 职责 | 关键边界 |
| --- | --- | --- |
| `ApiContract` | 定义逻辑目标系统、结构化 HTTP 请求和成功语义 | 不含环境 URL、认证信息或任意请求调试入口 |
| `PageContract` | 定义页面 route 和结构化元素定位 | P0 只支持批准的 locator；不支持 XPath/脚本 |
| `DataSet` | 发布修订内静态、共享、只读测试数据 | 不保存动态输出、凭据或环境配置 |
| `Flow` | 显式输入/输出的可复用步骤组合 | 不读取调用方隐式上下文，不隐藏身份 |
| `Scenario` | P0 业务流程执行单元，顺序组合 API、Browser、SQL 只读和转换 | 不声明外部 Scenario inputs，不支持 `when`/用户 retry |
| `Suite` | 显式、有序的 Scenario 列表 | 不按标签或路径动态生成成员 |
| `ApiCheckSet` | 单个 ApiContract 的稳定正/负向校验变体集合 | 认证/传输/平台异常不能伪装成预期业务失败 |

## 2. P0 Step 动作

P0 Step 只允许：`api.call`、`flow.call`、`browser.open`、`browser.click`、`browser.fill`、`browser.read`、`browser.screenshot`、`sql.query`、`data.transform`、`collection.map`。公共外壳、动作专属字段、执行顺序和 `wait`/`authRefresh` 重放资格以最小 DSL 为唯一字段语义权威。

## 3. 平台管理配置

以下不是 YAML 资产，由 Control 管理并使用不可变配置版本：测试项目、Git 资产源、环境、Target System、Managed Connection、Test Identity、认证 Profile、凭据、通知渠道、定时任务、权限映射、脱敏/保留策略和部署级出站策略。它们通过 Run Snapshot 固定版本引用，不得被资产正文复制或由 Worker 临时读取活动配置。

## 4. 跨组件协议资产

P0 协议实现必须在父仓库单一 `contracts/` 权威目录维护版本化 JSON Schema、正向样本、负向样本、错误码注册表和兼容矩阵，覆盖：

- Published Revision、ExecutableInvocation、Run Snapshot；
- CompileRequest、CompileResult、Plan；
- Worker capability、Claim、Lease、Fence、Material；
- Attempt、Event、Artifact 和统一错误响应；
- 权限 capability 及状态/错误映射。

该目录当前是已批准的交付约束，本轮基线归档不提前创建具体 Schema 或 fixtures；它们属于后续实施前的契约交付物，不得在两个组件仓库各自复制维护。

## 5. 首期黄金验收资产范围

首期必须能够用新 DSL 和新平台边界表达并验收：

| 编号 | 资产/流程 | 核心覆盖 |
| --- | --- | --- |
| GF-01 | E3E3 多 SKU 余额支付 | API 链路、多 SKU、身份、不可逆动作证据与不重放 |
| GF-02 | GO2 API 建单后 Browser 可见性验证与清理 | API/Browser 组合、`pageHandle`、跨通道身份和 cleanup |
| GF-03 | E3E3 多 SKU 部分售后与整批退款 | 稳定明细身份、售后/退款证据、不确定结果边界 |
| GF-04 | 固定测试用户 SQL 只读验证 | MySQL Managed Connection、参数化查询、有界结果 |
| AC-01 至 AC-19 | 平台能力验收场景 | 审计、通知、归档恢复、维护升级、定时所有权、密钥恢复、HTTPS、会话、用户、Worker、出站、幂等、并发冲突、活动修订、近期认证、备份恢复、保留清理和无配置包迁移 |

黄金流程中的旧系统名称、接口和业务字段只是验收证据与候选资产来源；正式资产必须遵守新领域模型、最小 DSL 和配置隔离规则。

## 6. 资产发布与运行约束

- Git 是 P0 YAML 唯一可写权威；平台只读同步、全根校验、整根原子发布。
- 任一非法资产都会阻止整个资产根发布，即使它未被当前 Scenario 引用。
- 发布修订、Snapshot 和 Plan 不可变并带摘要；Run 不得读取活动分支或可变配置补全执行语义。
- Adapter 随平台部署安装，不由 Web/YAML/Git 动态加载代码。
- 资产目录不包含业务凭据、平台账号、环境 URL、连接串、通知密钥或主密钥。
