# 旧系统参考边界

状态：初始产品基线派生索引；已随基线于 2026-09-24 确认。

## 1. 可作为只读证据的系统

- `testplat-new`
- `ai-test-platform`
- 旧 TestPlat 代码、配置、资产、运行记录和黄金流程来源材料

这些系统只能帮助识别真实业务流程、已有输入输出、认证路径、故障现象、验收数据和迁移风险，不是新平台产品、领域、DSL 或协议权威。

## 2. 允许提取的证据

- 黄金业务流程的真实动作顺序、跨系统/账号切换和稳定业务标识。
- API、Browser、SQL、认证 Redis 和通知渠道的实际接入条件。
- 已发生的超时、重复执行、选择器、数据关联、凭据泄露或报告缺失风险。
- 可重复的测试样本、mock 形状和验收事实；使用前仍需脱敏和适配新契约。

## 3. 明确禁止

- 直接复制旧领域模型、旧 DSL、旧执行器、公司专属业务代码或隐式全局状态。
- 把旧路径、类名、日志文本、数据库表或前端静态数据提升为新协议。
- 因旧系统支持某功能，就认定该功能进入 P0；P0 只由已批准产品和设计决定。
- 为了搬运而保留旧歧义、越权访问、凭据混用、动态脚本、最新一条数据选择或不安全重试。
- 让新平台在运行时依赖旧系统仓库、服务或数据模型。

## 4. 适配规则

任何旧能力进入新平台前必须依次完成：

1. 说明它解决的用户问题和可观察验收价值；
2. 对照当前产品、领域术语、DSL、架构和技术规格识别冲突；
3. 把旧实现细节转换为新平台稳定资产、配置、Adapter 或协议；
4. 补齐权限、失败、重放、审计、制品和保留边界；
5. 通过新平台契约测试与黄金验收，不以旧系统“能运行”作为完成证明。

## 5. 当前黄金流程的使用方式

GF-01 至 GF-04 可以引用 E3E3、GO2 等旧系统事实作为业务证据，但正式验收对象始终是新 TestPlat：发布修订、Run Snapshot、Plan、Worker Attempt/Event、制品、报告和权限审计。旧系统的成功结果不能替代新平台的协议与故障注入验收。
