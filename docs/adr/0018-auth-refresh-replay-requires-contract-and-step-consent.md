# 认证刷新重放需要 Contract 与 Step 双重同意

业务请求发出后才确认会话失效时，P0 默认只刷新后续鉴权并使当前请求失败；只有无业务副作用的只读 ApiContract 在 `spec.replay.allowedFor` 中允许 `authRefresh`，且当前 Step 同时申请该用途并说明理由，才能用冻结输入重试一次，最终资格取两者交集。平台不能从 HTTP 方法证明业务无副作用，因此 Contract 声明是作者的安全承诺，由拥有 `publish_asset` 的发布者随整个修订审阅并留痕，不增加专门审批流。创建、修改、支付、结算、退款等业务写入以及 Browser 动作不得声明该用途，也不借此开放网络故障重试或主动重复。双重授权让契约所有者控制可重放上限，同时允许场景作者按需收紧，避免把“重新登录”误当成任意业务请求重试。
