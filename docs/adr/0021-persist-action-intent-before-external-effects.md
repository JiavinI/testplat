# 外部动作前先持久化尝试事实

Worker 在发送 API 请求、执行 SQL 或操作浏览器之前，必须先持久化稳定 `attemptId`、目标、冻结输入摘要和 `started` 事件，结果事实持久化后才能进入下一 Step。事件使用稳定 `eventId` 支持至少一次投递和幂等去重；若动作可能已发生但结果无法确认，Run 以 `platform / ACTION_OUTCOME_UNKNOWN` 失败并禁止自动重放，同时跳过全部资产 cleanup，只执行 BrowserContext 销毁、租约释放等平台资源清理。该顺序不能消除外部系统与平台存储之间的原子性缺口，但能留下可审计的“不确定结果”证据，避免崩溃后把未知写操作当成未执行而重复下单、支付、退款或补偿。
