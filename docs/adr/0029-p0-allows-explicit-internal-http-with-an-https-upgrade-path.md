# P0 允许显式内网 HTTP 并预留 HTTPS 升级路径

P0 可以使用 `internal_http` 部署在受防火墙或 VPN 约束且不对公网开放的公司内网，不要求首期准备域名、证书、内部 CA 或 mTLS；部署方显式接受明文传输可能遭监听、会话劫持和内容篡改的剩余风险。平台同时提供 `https_required` 模式，并从第一天支持可配置外部基础地址、受限的可信代理头、HTTPS 下的 `Secure` Cookie、相对前端/API/WebSocket 地址和部署 Secret 挂载。后续可在反向代理增加域名与证书后切换模式，不迁移业务数据、不修改 DSL 或运行语义。这个取舍降低内部 P0 部署门槛，但不允许把内网 HTTP 暴露公网或在实现中写死 HTTP。
