## 已确认且本轮不重新访谈的约束

- Control 是发布、Run、队列、租约、事件、制品元数据和报告读模型的持久权威；Engine 无状态且只编译冻结输入；Worker 只受控执行。
- 已发布修订、Run Snapshot、Plan 内容不可变；新运行才读取活动修订，已形成快照的 Run 不受活动修订切换影响。
- P0 Scenario 外部输入为空；`InvocationInputBinding` 和 `ResolvedScenarioInputs` 仍走统一链路但固定为空。
- 编译在进入队列前完成；编译失败、超时或 Engine 不可用不得入队，保存为 `rejected + platform`。
- 协议主版本必须相同；次版本只允许已声明的可选扩展；未知必需语义拒绝；YAML 未知字段严格拒绝。
- Worker 失联、租约失效和不确定外部结果不得自动重放原 Run；`ACTION_OUTCOME_UNKNOWN` 跳过全部资产 cleanup，只做平台资源清理。
- 事件至少一次投递，按稳定 `eventId` 去重；制品先上传并校验，再在同一持久化事务中确认元数据和结果事件引用。

## 已确认的技术契约决策

用户于 2026-09-24 确认以下 10 组决定：

1. JSON 摘要采用 RFC 8785 JCS + SHA-256；发布根摘要基于排序 manifest，引用使用平台生成的 UUIDv7 不透明 ID。
2. Snapshot 保存不可变发布对象引用、closure manifest 与逐项摘要，不重复复制整根正文；被引用对象共同保留、备份和恢复。
3. Worker 在任务领取后取得完整不可变 Plan；凭据与敏感动作材料仍按 Step/Attempt 最小发放。
4. 协议版本使用整数 `major.minor`，配合 `requiredFeatures`/`optionalFeatures`；构建版本不参与兼容判断。
5. 租约使用 Control/PostgreSQL 服务端时间；Worker 提交连续 `producerSequence`，Control 校验并分配 Run canonical sequence；候选租约 30 秒、每 10 秒 heartbeat、无隐藏宽限期，最终数值经故障 prototype 校准。
6. Snapshot/Plan 按任务租约授权，敏感材料按 Step/Attempt 授权；P0 制品由 Control 流式代理上传，未来对象存储短期凭证不改变外部协议。
7. 迟到证据保存为 `lateSupplemental`，不进入正常结果或趋势；动作前失联使用 `WORKER_LEASE_LOST_BEFORE_ACTION`，started 后结果不明使用 `ACTION_OUTCOME_UNKNOWN`。
8. 权限目录增加运行、masked 数据、趋势、项目配置和定时任务的稳定 capability。
9. HTTP/协议错误与 Run/Step 失败分类分层；敏感对象采用防枚举响应；高敏感操作审计失败关闭，普通 masked 查询不依赖逐次敏感审计。
10. 父仓库建立单一 `contracts/` 权威目录，保存版本化 Schema、正反样本和兼容矩阵，组件仓库固定引用同一版本。

仍需通过 prototype 或实现期测试校准的数值参数属于技术验证项，不再作为产品或架构决策重新访谈；实测不得静默改变上述契约或已批准的 PRD、DSL、架构语义。
