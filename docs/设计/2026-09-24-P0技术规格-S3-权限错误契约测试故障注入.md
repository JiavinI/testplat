## 2. 权限边界矩阵

角色名称只提供初始模板；代码必须按稳定 capability 判定，不能写死角色名。下表的 `allow` 是最小边界，具体授权仍由可配置映射决定。

| 主体 | 允许 | 明确禁止 | 失败关闭/审计 |
| --- | --- | --- | --- |
| 已认证平台用户 | 按当前能力浏览项目、创建允许的手动 Run、查询获权报告 | 通过入口参数改变 Snapshot、读取凭据明文、越权读取其他用户的 masked 结果 | CSRF+Origin+会话；创建/查询按审计策略记录 |
| `publish_asset` 用户 | 从已保存且全根校验通过的同步提交发布/激活兼容修订 | 任意 SHA、单资产发布、Git 写回、绕过兼容校验 | 发布/激活/冲突审计；审计失败不提交 |
| `manage_authorization` | 修改角色/能力映射、维护授权 | 删除/撤权所有可管理账号导致锁死 | 最近认证；事务和审计失败关闭 |
| `view_revealable_run_data` | 在线查看获权 Run 的 revealable 结构化数据 | 直接取得 raw、下载/导出、改变脱敏策略 | 每次揭示按当前授权校验并审计 |
| `view_raw_run_data` | 在线查看 raw 业务请求/响应等获权原始数据 | 查看平台账号/Git/受控连接凭据；下载/导出 | 当前授权+审计；审计失败不返回值 |
| `reveal_credential` | 按最近认证查看/复制被测系统凭据 | 查看平台主密钥、其他租户/项目（P0 无项目级授权） | 最近 15 分钟密码认证；审计失败不返回值 |
| 调度器服务身份 | 按已保存任务版本创建定时 ExecutableInvocation | 伪装创建者、修改资产/权限、读取报告 raw | 触发事件标注调度器身份和任务版本 |
| Engine 服务身份 | 读取指定 Snapshot、提交 CompileResult | 读取凭据明文、修改 Run/队列/配置、调用测试出站 | 仅服务到服务认证；摘要/版本校验；失败关闭 |
| Worker 服务身份 | 声明能力、领取自身兼容任务、读取当前任务最小材料、上传制品、提交事件 | 用户/角色/授权/普通配置、任意 Run、直接数据库/Redis/文件系统、补编译 | 当前 lease+fence；每次凭据使用/领取/撤销审计 |
| 报告投影器/通知 Adapter | 读结构化事实并按策略生成投影/通知 | 改写 Run/Step/Attempt/Artifact 事实、读取未授权 raw | 投影重建幂等；通知失败不改 Run 结果 |

### 2.1 已确认补充的 capability

在 PRD 已列能力之外，P0 权限目录增加：`create_run`、`view_run_summary`、`view_masked_run_data`、`view_trend`、`manage_project_config`、`manage_schedule`。角色初始模板必须通过这些稳定标识表达，控制面、Engine 和 Worker 不得恢复按角色名写死权限分支。

## 3. 错误响应包

所有 HTTP/JSON 接口使用同一外层，不回显凭据、完整请求、Cookie、Token 或平台内部路径：

```json
{
  "error": {
    "code": "IDEMPOTENCY_CONFLICT",
    "message": "stable human-readable message",
    "stage": "invocation|snapshot|compile|queue|lease|event|artifact|report",
    "retryable": false,
    "details": {},
    "requestId": "<opaque-id>"
  }
}
```

HTTP/协议层使用独立稳定的 `code + stage`，不强制把每个接口错误归入 Run/Step 十类失败。只有错误形成持久化 Run/Step 拒绝或失败事实时，响应才附加 `failureCategory`，并映射到 PRD 的十类失败类别。`message` 可本地化但不能承载机密；`details` 只提供最小可行动信息，例如支持版本、冲突版本、队列原因或原确认引用。未知扩展字段可忽略，未知必需语义不得忽略。

### 3.1 HTTP 到业务错误映射

| HTTP | 典型场景 | 规则 |
| --- | --- | --- |
| 400 | JSON/YAML 结构非法、未知字段、字段与 action 不匹配 | 不创建 Snapshot/Attempt；返回字段定位但不回显秘密值 |
| 401 | Web 会话/服务身份缺失或失效 | 未认证统一返回 401，不泄露主体是否存在；服务端记录安全事件 |
| 403 | 已认证主体可见对象但缺少操作 capability、最近认证过期 | 不返回受保护内容；按需要审计 |
| 404 | 对象不存在，或已认证主体无权知道敏感对象是否存在 | 统一不可见响应，避免枚举 |
| 409 | 幂等冲突、状态转移冲突、重复 ID 异内容、fence 失效 | 返回原确认/当前状态/冲突引用，不自动重试外部动作 |
| 412 | `expectedVersion` 或内容摘要前置条件不匹配 | 不覆盖已有配置/事实 |
| 413 | 制品或请求超过大小上限 | 记录配额失败，不静默丢弃 |
| 422 | 语义校验、能力/版本不兼容、非空 Scenario 输入 | 不入队、不执行外部动作 |
| 429 | 全局 queued 容量或受管接口限流 | 只有明确可重试的入口可返回重试提示；不重放 Run |
| 503 | Engine/Control/ArtifactStore 暂不可用 | 编译阶段保存 `rejected + platform`；执行阶段按 S2 unknown 规则，不自动重派 |

错误码注册表和 Run/Step 状态映射必须存入共享契约目录并遵循向后兼容规则；HTTP 状态不能替代持久化失败事实。Engine、Worker、调度器和投影器的服务身份撤销从下一次请求立即生效，不缓存授权；进行中 Worker 租约必须在一个租约周期内封闭。所有轮换、撤销和拒绝记录主体、凭据版本、发生时间、结果及非敏感原因，不记录凭据正文。

### 3.2 审计失败关闭范围

raw/revealable 查看、凭据查看/复制/使用、发布、授权和其他高敏感配置变更必须在审计写入失败时失败关闭。普通 masked 查询不要求逐次写敏感审计事件，不因审计子系统暂时不可用而阻断；其访问仍受当前授权、普通访问日志和安全监控约束。

## 4. 契约测试分层

测试只验证可观察协议和事实，不绑定内部类名或数据库表布局。

父仓库建立单一 `contracts/` 权威目录，保存版本化 JSON Schema、正向样本、负向样本、错误码注册表和兼容矩阵。`testplat-control` 与 `testplat-engine` 的 CI 必须固定引用同一契约版本，禁止各自复制维护协议样本；协议变更先更新权威目录及兼容测试，再由各组件消费。

### 4.1 S1 发布/快照/编译

- 发布完整资产根：非法未引用 YAML 也阻止整个修订；发布内容、commit、摘要和验证结果不可变。
- 活动修订发布/回退并发：原子切换，历史 Snapshot/Run 不变；不兼容 DSL/操作符/Adapter/Worker 能力拒绝。
- 同一 Invocation 幂等：相同内容返回原 Run，不重复 Snapshot/队列；不同内容冲突。
- Snapshot 脱敏：无凭据明文，冻结环境/连接/能力/身份/策略/通知版本；P0 Scenario 输入为空。
- 编译确定性：同一 Snapshot 得到相同 Plan 摘要；摘要篡改、未知必需语义、版本主版本不匹配、能力缺失均在入队前拒绝。
- Plan 持久化：Engine 返回正文后 Control 验证并保存；Engine 不成为 Plan 存储权威，Worker 不能从 Engine 直接取计划。

### 4.2 S2 领取/租约/事件/制品

- FIFO 和原子全租约：多身份 Run 不部分占有；共享键按 `queuedAt` 排队，无关身份不被阻塞。
- Fence：旧 lease/fence 的 heartbeat、material、event、artifact 全部拒绝；迟到 evidence 不改终态。
- Attempt 顺序：started 未确认时没有外部动作；result 未确认不能进入下一 Step；同一事件重投不生成新 attempt。
- 事件幂等：同 ID 同内容原确认；同 ID 异内容冲突；非法状态转移拒绝；缺序不静默排序。
- Artifact：大小/摘要/权限/配额校验，上传成功但事务失败不产生已确认引用；重建报告不重复计数。
- Worker 撤销/重启/Control 恢复：已受理 Run、Snapshot、Attempt、事件和制品元数据可恢复；原 Run 不自动重派。

### 4.3 S3 权限/错误

- 每个 capability 的 allow/deny 矩阵覆盖 Web、Engine、Worker、调度器、投影器；越权响应不泄露对象存在性或秘密。
- 所有状态改变请求具备 CSRF/Origin/会话或服务身份校验；高影响用户操作要求最近认证；高敏感操作审计写入失败时失败关闭，普通 masked 查询不依赖逐次敏感审计。
- 版本冲突、幂等冲突、围栏冲突、摘要冲突和能力不兼容返回稳定错误包，且不改变事实。
- masked/revealable/raw 当前权限即时生效；报告查询、揭示、raw 访问和凭据使用都产生审计事实。

## 5. 故障注入验收矩阵

| 注入点 | 预期持久事实 | 禁止行为 |
| --- | --- | --- |
| Git 同步途中分支移动/远端不可用 | 固定 commit 的同步/失败事实 | 读最新分支补全或发布半根资产 |
| 发布事务提交前数据库断开 | 无活动切换或半修订 | 部分发布可运行 |
| Compile 超时/Engine 503 | `rejected + platform`，可查询 requestId | 入队、后台偷偷重试成 Run |
| Snapshot/Plan digest 篡改 | 协议错误/拒绝审计 | 接受“最新摘要”或重新解释正文 |
| 队列满/项目归档/凭据紧急撤销 | `rejected + policy/configuration` | 自动切换凭据或创建替代 Run |
| claim 后 Worker 被杀 | 失联封闭、平台失败或 unknown | 自动重派原 Run |
| started 事件后外部调用与结果之间断网 | `ACTION_OUTCOME_UNKNOWN` | 自动重放、资产 cleanup、业务补偿 |
| event 重复/乱序/异内容 | 原确认、顺序错误或协议冲突 | 重复计数、最后写入覆盖 |
| ArtifactStore 上传/校验/事务/对象恢复故障 | 孤儿/损坏/失败结构化记录 | 丢证据仍标记通过、公开对象 URL |
| 审计库不可用 | 敏感查看/凭据使用/授权变更失败关闭 | 返回 raw、提交权限变更但无审计 |
| 报告投影重复运行 | 同一事实一次计数 | 改写事实、重复趋势样本 |
| 恢复到隔离环境 | 可说明恢复点、修订/历史 Run 可读 | 自动重放未完成 Run |

验收还需覆盖已批准指标：手动 Run 创建 p95 ≤ 3 秒、常用查询 p95 ≤ 2 秒、终态后 30 秒内可查看报告、参考槽位 10 API/SQL + 3 Browser、最多 1000 queued、RPO ≤ 24 小时和 RTO ≤ 4 小时。指标测量必须在参考单机拓扑和专用测试环境中完成，不能用草案推理代替实测。

## 6. 已确认的技术契约决定与验证项

用户于 2026-09-24 确认：

1. 权限目录新增 `create_run`、`view_run_summary`、`view_masked_run_data`、`view_trend`、`manage_project_config`、`manage_schedule`。
2. HTTP/协议错误使用独立稳定 `code + stage`；只有形成 Run/Step 事实时才映射 PRD 十类 `failureCategory`，错误码注册表按兼容规则演进。
3. 未认证统一 401；已认证但无权知道敏感对象是否存在时返回 404；对象可见但缺少操作能力时返回 403。
4. 服务身份撤销从下一次请求立即生效，不缓存授权；进行中 Worker 租约在一个租约周期内封闭，轮换/撤销/拒绝均写非敏感审计事实。
5. raw/revealable、凭据、发布、授权和高敏感配置变更审计失败关闭；普通 masked 查询不依赖逐次敏感审计。
6. 父仓库 `contracts/` 是 Schema、正反样本、错误码和兼容矩阵的单一权威，组件 CI 固定消费同一版本。

服务身份轮换的常规有效期、提前轮换窗口等运维数值可在安全测试后作为部署参数冻结，但不得放宽即时撤销、最小授权和审计边界。若后续发现任何选择需要改变状态集合、自动重放边界、服务职责或权限原则，必须单列影响并暂停。
