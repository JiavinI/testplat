# TestPlat 最小领域专用语言设计

日期：2026-09-21

状态：已批准

批准记录：用户于 2026-09-21 确认“最小 DSL 设计审核通过”。
范围：仅冻结首期 YAML 资产、值节点、Step、认证、执行顺序和 P0 约束；不进入代码实现、数据库模型或实施计划。

## 1. 设计目标与边界

TestPlat 是全新的通用测试执行平台：控制面管理并发布版本化 YAML 资产，Engine 将已发布修订编译为确定性执行计划，Worker 执行 API、Browser、SQL 只读查询和受控数据转换，平台保存运行、步骤时间线、请求响应、断言、制品、报告和趋势。ES 不属于 P0。

更换公司或项目时，只替换测试资产、环境绑定、凭据引用和专用 Adapter，不修改通用内核。本 DSL 不把 testplat-new 的旧字段、旧执行器或业务模型直接作为新平台依赖；旧系统只提供能力和风险审计证据。

本设计与 [产品需求规格.md](../产品需求/产品需求规格.md) 的关系是：PRD 定义产品范围和优先级，本文件把已确认的最小 DSL 语义整理成可供后续 Schema、Compiler 和 Worker 共同实现的设计输入。

## 2. 统一资产外壳

每个 YAML 文件只有一个资产，使用严格公共外壳：

~~~yaml
apiVersion: testplat.io/v1
kind: Scenario

metadata:
  id: order.createAndPay
  name: 创建并支付订单
  description: 创建订单并完成支付
  tags:
    - smoke

spec: {}
~~~

约束：

- apiVersion 是 DSL Schema 版本，不是 Git 修订或业务版本。v1 语义不能静默改变。
- kind 首期只允许 ApiContract、PageContract、DataSet、Flow、Scenario、Suite、ApiCheckSet。
- metadata.id 在同一测试项目内跨资产类型全局唯一；引用使用稳定 ID，不使用文件路径。
- metadata.name 是展示名称；description、tags 可选，标签不能动态决定 Suite 成员。
- 未知根字段、未知 metadata 字段和未知 spec 字段必须在发布前拒绝。
- 环境地址、密码、Token、Cookie、连接串和其他认证机密不进入 YAML。

## 3. 值节点、作用域与类型

### 3.1 值节点

首期值节点只有四种：

~~~yaml
# 确定地址
orderNo:
  $ref: steps.createOrder.outputs.orderNo

# 复杂查询、多结果或可选匹配
order:
  $select:
    from:
      $ref: result.body
    path: $.data.orders[?(@.status == $params.expectedStatus)]
    params:
      expectedStatus: CREATED
    expect: one

# 确定性字符串渲染
remark:
  $template:
    text: 自动化订单-{orderNo}
    with:
      orderNo:
        $ref: steps.createOrder.outputs.orderNo

# 递归关闭值节点解析
payload:
  $literal:
    $ref: 这是业务对象中的原始字段
~~~

$ref 优先用于固定、唯一地址；$select 仅用于通配、过滤、可选匹配或多结果查询；$template 始终输出字符串；$literal 只用于原样传递包含保留键的业务数据。值节点结构必须严格匹配，混入未知字段时发布拒绝。

$ref 首期保留根：

| 根 | 含义 | 作用域 |
| --- | --- | --- |
| datasets | Scenario 或 ApiCheckSet 绑定的静态 DataSet | 当前运行 |
| vars | Scenario 局部变量 | 当前 Scenario |
| inputs | 当前可调用资产的显式输入 | 当前 Flow、ApiContract 或 Page route |
| steps | 当前作用域中此前步骤的公开输出 | 当前 Flow/Scenario |
| result | 当前 Step 的标准动作结果 | 当前 Step 的 wait/assertions/outputs |

禁止读取环境、凭据、Token、Cookie、连接信息、全局进程变量或后置步骤。Scenario 不能穿透 Flow 内部步骤；Flow 不能直接读取调用方的 datasets 或 vars，必须通过输入接收。

### 3.2 类型

普通可序列化资产值固定为：string、integer、decimal、boolean、date、datetime、object、list、json。object 默认封闭且声明字段，list 必须声明元素类型，json 是显式逃生口。required 表示能否缺失，nullable 表示已存在的值能否为 null；不提供默认值、联合类型、递归类型、类型继承或隐式类型转换。

`pageHandle` 是 Browser 页面实例专用的不透明运行时能力类型，不属于上述九种普通资产值，也不等同于 string。它只能由 Browser 动作产生，只能在同一 Run、同一 BrowserContext 内作为 Step 或 Flow 输入输出传递；不能进入 DataSet、Scenario 外部输入、ApiContract/Page route 输入、json、模板或 data.transform，也不能持久化后恢复使用。报告只保存不可复用的显示标识和页面元数据。

## 4. DataSet：静态、共享、只读

DataSet 是运行前确定的业务测试数据，不是运行时变量仓库，也不能读取或修改任何步骤响应。共享范围为单个测试项目及其已发布修订；Scenario 和 ApiCheckSet 可直接绑定多份 DataSet，Flow 必须通过 inputs 接收，其他 Contract 不直接读取。不同环境的档案由平台环境绑定选择。

~~~yaml
apiVersion: testplat.io/v1
kind: DataSet

metadata:
  id: commerce.common
  name: 订单生命周期公共数据
  description: 下单和拿货流程共用的静态业务数据
  tags: [commerce, shared]

spec:
  profiles:
    test-standard:
      values:
        items:
          - keyword: 测试商品
            productNumber: TEST-P001
            sku:
              color: 红色
              size: M
            quantity: 1
        receiver:
          name: 自动化测试用户
          mobile: "13800000000"
          address: 上海市测试区测试路1号
        delivery:
          expressCode: YD
        order:
          currency: CNY
          remarkPrefix: AUTO-TEST

    dev-standard:
      values:
        items:
          - keyword: DEV测试商品
            productNumber: DEV-P001
            sku:
              color: 红色
              size: M
            quantity: 1
        receiver:
          name: 开发环境测试用户
          mobile: "13900000000"
          address: 上海市开发环境测试地址
        delivery:
          expressCode: SF
        order:
          currency: CNY
          remarkPrefix: AUTO-DEV
~~~

下单和拿货两个 Scenario 都可以绑定 commerce.common，只维护一份商品、收件人和配送数据。订单号等动态值永远来自 steps.<id>.outputs.*；需要编辑动态值时使用新的 data.transform Step，不回写 DataSet。

## 5. ApiContract

ApiContract 绑定逻辑 targetRef，把调用者输入映射到结构化 HTTP 请求；环境地址由平台绑定解析，认证头由认证 Profile 注入。pathParams、query、headers 和 body 可以同时存在，body 首期支持 JSON 与 form。

~~~yaml
apiVersion: testplat.io/v1
kind: ApiContract

metadata:
  id: api.order.create
  name: 创建订单
  description: 创建一个待支付订单
  tags: [order, write]

spec:
  targetRef: commerce-api

  request:
    method: POST
    path: /api/orders
    inputs:
      items:
        type: list
        required: true
        items:
          type: json
      receiver:
        type: object
        required: true
        fields:
          name: {type: string, required: true}
          mobile: {type: string, required: true}
          address: {type: string, required: true}
      remark:
        type: string
        required: false
      requestId:
        type: string
        required: true

    headers:
      X-Request-Id:
        $ref: inputs.requestId
      X-Business-Source: testplat

    body:
      mediaType: application/json
      value:
        items:
          $ref: inputs.items
        receiver:
          $ref: inputs.receiver
        remark:
          $ref: inputs.remark

  response:
    body:
      decodeAs: json
    success:
      status: [200, 201]
      assertions:
        - id: business_code
          actual:
            $ref: result.body.code
          op: eq
          expected: 0
        - id: order_no_exists
          actual:
            $ref: result.body.data.orderNo
          op: exists
~~~

认证或会话头不能由 Contract 或 Step 任意覆盖。标准结果至少提供 result.status、result.headers、result.body、result.meta.durationMs；HTTP 状态成功规则先于 Step 断言。decodeAs 首期为 json、text、binary、none。`spec.replay.allowedFor: [authRefresh]` 只允许无业务副作用的只读 ApiContract 声明，表示契约允许的最大范围；创建、修改、支付、结算、退款等 Contract 禁止声明。

只读 Contract 与调用 Step 必须分别声明，最终资格取交集：

~~~yaml
# 无业务副作用的只读 ApiContract
spec:
  replay:
    allowedFor: [authRefresh]

# 调用该 Contract 的 api.call Step
replay:
  allowedFor: [authRefresh]
  reason: 订单状态查询无业务副作用
~~~

## 6. PageContract

PageContract 描述逻辑目标系统中的页面入口和稳定元素，不保存绝对 URL、认证信息或账号。targetRef 必填，route 可选；只能通过点击、重定向、弹窗或第三方流程到达的动态页面可以没有 route。P0 Browser Adapter 只认证 Playwright Chromium 并默认无头执行，浏览器构建标识进入 Worker 能力声明和运行快照；Firefox、WebKit 和系统 Chrome 不属于 P0。

~~~yaml
apiVersion: testplat.io/v1
kind: PageContract

metadata:
  id: page.admin.orderDetail
  name: 管理后台订单详情页
  tags: [order, browser]

spec:
  targetRef: commerce-admin

  route:
    path: /orders/{orderNo}
    inputs:
      orderNo:
        type: string
        required: true
    pathParams:
      orderNo:
        $ref: inputs.orderNo

  elements:
    status:
      locator:
        by: testId
        value: order-status
    searchInput:
      locator:
        by: label
        value: 订单号
        exact: true
    payButton:
      within:
        - by: css
          value: .order-actions
      locator:
        by: role
        role: button
        name: 立即支付
        exact: true
    paymentPassword:
      frames:
        - by: css
          value: 'iframe[src*="/open/gateway"]'
      locator:
        by: css
        value: '#password'
~~~

定位方式首期为 role、label、text、testId、css。`css` 只接受固定 Playwright/Chromium 构建交给浏览器执行的标准 CSS，不接受 Playwright 文本引擎、XPath 前缀、`>>` 组合语法或其他私有扩展。frames、within、locator 从外到内解析，每一级必须严格唯一匹配；P0 不支持 XPath、JavaScript、自动取第一项、候选回退或 Playwright 私有选择器。后续 XPath 必须通过新 DSL 版本增加独立 `xpath` 策略和受限语法，不能复用 `css` 字段。

`pageRef` 只引用 PageContract；运行时页面实例使用当前 Run 内生成的 `pageHandleRef`。`browser.open` 在 `result.page.handleRef` 返回 `pageHandle` 类型句柄，后续 Browser Step 必须通过显式输出传递该句柄。点击未打开新页面时返回原句柄，恰好打开一个新页面时返回新句柄，同时打开多个新页面时失败。BrowserContext 按 `(runId, environment, targetRef, actorRef)` 隔离，同一 Run 内复用，Run 结束后销毁；缓存的 Cookie/Storage State 只能初始化新 Context，不能复用 Context 实例。

## 7. Flow：可复用但不隐藏依赖

Flow 不是直接运行入口，必须声明类型化输入、步骤和根级输出。Flow 不直接读取 DataSet 或调用方局部变量，调用者只能读取 Flow 的公开输出。

~~~yaml
apiVersion: testplat.io/v1
kind: Flow

metadata:
  id: flow.order.create
  name: 创建订单流程

spec:
  inputs:
    items:
      type: list
      required: true
      items: {type: json}
    receiver:
      type: json
      required: true
    requestId:
      type: string
      required: true

  steps:
    - id: createOrder
      name: 创建订单
      action: api.call
      contractRef: api.order.create
      auth:
        actorRef: buyer
      inputs:
        items:
          $ref: inputs.items
        receiver:
          $ref: inputs.receiver
        requestId:
          $ref: inputs.requestId
      outputs:
        orderNo:
          type: string
          value:
            $ref: result.body.data.orderNo

  outputs:
    orderNo:
      type: string
      value:
        $ref: steps.createOrder.outputs.orderNo
~~~

Flow 内 API/Browser Step 各自声明 auth；Flow 不继承调用方默认账号。调用者不能读取 createOrder 以外的内部技术结果。

## 8. Scenario：跨系统、跨账号、API/Browser/SQL 组合

下面示例展示一条完整业务链路。它使用公共 DataSet，通过 API 创建订单，再用 SQL 只读查询确认数据库状态，切换到后台账号使用 Browser 验证，并在主流程结束后执行清理。

~~~yaml
apiVersion: testplat.io/v1
kind: Scenario

metadata:
  id: scenario.order.createAndVerify
  name: 创建订单并验证多系统状态
  description: 跨商城 API、订单库和管理后台验证订单链路
  tags: [smoke, order]

spec:
  datasets:
    common:
      dataSetRef: commerce.common

  vars:
    expectedStatus: CREATED

  steps:
    - id: createOrder
      name: 创建订单
      action: flow.call
      flowRef: flow.order.create
      inputs:
        items:
          $ref: datasets.common.items
        receiver:
          $ref: datasets.common.receiver
        requestId: scenario-create-and-verify
      outputs:
        orderNo:
          type: string
          value:
            $ref: result.outputs.orderNo

    - id: waitOrderInDatabase
      name: 等待订单写入数据库
      action: sql.query
      connectionRef: commerce-order-read
      statement: >-
        SELECT order_no, status, amount
        FROM orders
        WHERE order_no = :order_no
      params:
        order_no:
          $ref: steps.createOrder.outputs.orderNo
      maxRows: 1
      wait:
        intervalMs: 2000
        maxAttempts: 15
        until:
          assertions:
            - id: database_row_exists
              actual:
                $ref: result.meta.returned
              op: gt
              expected: 0
      replay:
        allowedFor: [wait]
        reason: 只读订单查询可安全重复执行
      assertions:
        - id: database_status
          actual:
            $ref: result.rows[0].status
          op: eq
          expected:
            $ref: vars.expectedStatus
      outputs:
        databaseOrder:
          type: json
          value:
            $ref: result.rows[0]

    - id: openOrderInAdmin
      name: 后台打开订单
      action: browser.open
      pageRef: page.admin.orderDetail
      auth:
        actorRef: operator
      inputs:
        orderNo:
          $ref: steps.createOrder.outputs.orderNo
      outputs:
        pageHandle:
          type: pageHandle
          value:
            $ref: result.page.handleRef

    - id: readAdminStatus
      name: 读取后台订单状态
      action: browser.read
      pageRef: page.admin.orderDetail
      pageHandleRef:
        $ref: steps.openOrderInAdmin.outputs.pageHandle
      elementRef: status
      auth:
        actorRef: operator
      assertions:
        - id: admin_status
          actual:
            $ref: result.element.text
          op: eq
          expected: CREATED
      outputs:
        statusText:
          type: string
          value:
            $ref: result.element.text

  cleanup:
    - id: captureFailureEvidence
      name: 保存后台截图
      action: browser.screenshot
      pageRef: page.admin.orderDetail
      pageHandleRef:
        $ref: steps.openOrderInAdmin.outputs.pageHandle
      auth:
        actorRef: operator
~~~

说明：

- createOrder 的输出是当前运行上下文，不会写回 DataSet。
- API、Browser Step 分别声明 buyer、operator，流程可以多次切换账号；不共享隐式认证状态。
- SQL 使用受控连接，不声明 auth。
- P0 只认证 MySQL 受控连接；PostgreSQL 是后续 Adapter，SQLite 仅供实现测试，不是产品连接。
- wait 不是按 HTTP 方法或动作名称自动放行；只有显式 replay.allowedFor: [wait] 才能重放。
- API 请求发送前确认 Token/Session 失效时自动重新登录后再发送，不算业务重放。请求发送后才收到会话失效信号时，默认更新后续鉴权但当前 Step 失败；只有无业务副作用的只读 ApiContract 与当前 Step 都显式允许 `authRefresh`，才能以冻结输入重试一次。已有页面句柄的 Browser 动作失效后不自动重建或重放。
- P0 不支持 when、用户配置 retry 或任意循环；collection.map 仅按声明的有限列表顺序调用 Flow。
- cleanup 独立记录，不能覆盖主流程失败；缺失页面或输出时明确记录跳过原因。

## 9. 动态数据加工

原始 Step Output 不可变。简单一次性字符串可以用 $template；金额计算、对象重组、列表筛选、分组和可复用加工必须使用 data.transform，产生新的输出。操作符属于版本化注册表，不执行任意 Python、JavaScript、Shell，也不加入公司专属函数。

~~~yaml
- id: buildRefundRequest
  name: 生成退款请求
  action: data.transform
  operator: object.compose
  inputs:
    orderNo:
      $ref: steps.createOrder.outputs.orderNo
    amount:
      $ref: steps.waitOrderInDatabase.outputs.databaseOrder.amount
    reason:
      $template:
        text: 自动化退款-{orderNo}
        with:
          orderNo:
            $ref: steps.createOrder.outputs.orderNo
  outputs:
    refundRequest:
      type: json
      value:
        $ref: result.value
~~~

首期只冻结操作符注册表边界和扩展规则；具体最小清单应根据至少两个真实通用场景逐项实现和审查。

## 10. Suite

Suite 是显式、有序的 Scenario 列表，不通过标签或文件路径动态决定正式成员。失败立即停止或继续执行由任务/单次运行配置决定，并写入运行快照。

~~~yaml
apiVersion: testplat.io/v1
kind: Suite

metadata:
  id: suite.order.smoke
  name: 订单冒烟集合
  tags: [smoke, order]

spec:
  members:
    - scenarioRef: scenario.order.createAndVerify
    - scenarioRef: scenario.order.createAndPay
~~~

## 11. ApiCheckSet

ApiCheckSet 面向单接口校验。每个变体都有稳定 ID 和独立结果；同一集合的所有变体共享 spec.auth，不能隐式使用平台默认账号。

~~~yaml
apiVersion: testplat.io/v1
kind: ApiCheckSet

metadata:
  id: checks.order.create
  name: 创建订单接口校验
  tags: [api, order]

spec:
  contractRef: api.order.create
  auth:
    actorRef: buyer
  variants:
    - id: missing_items
      name: 缺少商品
      inputs:
        items: []
        receiver:
          name: 自动化测试用户
          mobile: "13800000000"
          address: 上海市测试区测试路1号
        requestId: check-missing-items
      expect:
        status: [400]
        assertions:
          - id: error_code
            actual:
              $ref: result.body.errorCode
            op: eq
            expected: PARAM_MISSING

    - id: valid_order
      name: 合法订单
      inputs:
        items:
          - productNumber: TEST-P001
            quantity: 1
        receiver:
          name: 自动化测试用户
          mobile: "13800000000"
          address: 上海市测试区测试路1号
        requestId: check-valid-order
      expect:
        status: [200, 201]
~~~

变体结果使用稳定组合标识，例如 checks.order.create#missing_items。P0 的负向变体可以声明预期 Contract 失败，但必须同时断言预期 HTTP 状态和至少一项稳定业务错误；全部满足时变体通过。认证、传输、超时、动作或平台异常不能算作预期业务失败，也不能用通用开关关闭 Contract 成功语义。该覆盖只存在于 ApiCheckSet 变体，普通 Scenario 仍执行 Contract 的正常成功规则。

## 12. Step 公共外壳与执行顺序

Step 采用平铺公共字段加 action 判别动作专属字段。

公共字段：id、name、action、auth、timeoutMs、assertions、outputs、wait、replay。API/SQL 动作默认超时 30 秒，Browser 动作默认超时 60 秒；`timeoutMs` 只能在平台允许范围和 Run 剩余预算内调整。P0 的 `replay.allowedFor` 只允许 `wait` 与 `authRefresh`；后者要求无业务副作用的只读 ApiContract 在 `spec.replay.allowedFor` 中给出上限，且当前 Step 同时申请并说明理由，最终资格取交集，最多使用一次。P0 不开放网络错误重试、用户配置重试或主动重复。

动作专属字段：

| action | 字段 |
| --- | --- |
| api.call | contractRef、inputs |
| flow.call | flowRef、inputs |
| browser.open | pageRef、inputs |
| browser.click | pageRef、pageHandleRef、elementRef |
| browser.fill | pageRef、pageHandleRef、elementRef、value |
| browser.read | pageRef、pageHandleRef、elementRef |
| browser.screenshot | pageRef、pageHandleRef |
| sql.query | connectionRef、statement、params、maxRows |
| data.transform | operator、inputs |
| collection.map | source、flowRef、inputs |

API/Browser 必须显式二选一：auth.actorRef 或 auth.mode: anonymous。SQL、Flow 调用、数据转换和集合执行不得声明 auth。Step ID 在同一 steps + cleanup 作用域唯一。P0 拒绝未知字段、字段与 action 不匹配、when、retry 和 `es.search`。

每个 Step 的确定性执行顺序：

~~~text
解析并校验输入
→ 执行动作
→ 执行 Contract 成功语义
→ 按 wait 进行有界重复并记录每次尝试
→ 执行 Step assertions
→ 计算并校验 outputs
→ 发布不可变输出
~~~

任一阶段失败都不得发布部分输出。result 只在当前 Step 的 wait、assertions、outputs 中可见；后续步骤只能读取已发布的 steps.<id>.outputs.*。

## 13. 失败、报告与安全边界

Run 状态为 queued、running、passed、failed、cancelled、rejected；Step 状态为 pending、running、passed、failed、skipped、cancelled。失败类别与状态分离，类别包括 asset、configuration、policy、data、auth、transport、timeout、action、assertion、platform。

P0 的执行必须有界：排队默认最多 24 小时并可全局配置为 1 至 72 小时；单个 wait 最多 10 分钟；Run 主执行最多 2 小时，结束后 cleanup 最多再使用 10 分钟。Suite、ApiCheckSet、collection.map 分别最多 100 个成员、变体和集合项；一个 Run 最多产生 1000 个动作实例，包含展开调用、cleanup 和重复尝试；`sql.query.maxRows` 最大为 1000。单个响应体或制品最大 50 MiB，单 Run 制品累计最大 500 MiB。静态可知的超限在发布或编译时拒绝，运行时超限以结构化 `policy`、`timeout` 或 `action` 失败结束，不静默截断或跳过，SQL 合法 `maxRows` 截断除外。

每次外部动作在执行前必须先持久化稳定 `attemptId`、冻结输入摘要和 `started` 事件；结果事实未持久化前不得进入下一 Step。事件以稳定 `eventId` 支持至少一次投递和幂等去重；无法持久化时不发起新动作，已可能发生但结果未知时以 `platform / ACTION_OUTCOME_UNKNOWN` 失败且不自动重放。Run 终态后 30 秒内生成可查看报告。

`ACTION_OUTCOME_UNKNOWN` 发生后不执行任何资产 cleanup，也不自动查询、取消、补偿或回滚业务状态；只执行 BrowserContext 销毁、身份租约释放等平台资源清理。所有被跳过 cleanup 必须记录 `OUTCOME_UNKNOWN` 原因，后续处理由用户基于证据显式发起新的 Run。

每次运行保存总体结果、步骤时间线、实际请求响应、UI 截图、断言结果、失败原因、变量和制品；原始证据加密保存，普通日志不得输出其完整值。报告访问模式为 masked、revealable、raw，具体权限由平台配置而非 DSL 或 Worker 代码写死；项目定义默认脱敏规则，目标系统可以覆盖，运行快照记录当次策略版本。获权 raw 视图可以显示实际业务请求中的认证头、Token、Cookie、被测系统登录密码、支付密码和验证码，查看必须审计。截图是 P0 例外：不做图片脱敏、不设截图专属权限，拥有 Run 查看权限的用户可以在线查看原始截图；P0 不提供截图、raw 请求响应或其他原始制品下载/导出。平台账号密码、Git 凭据和受控连接凭据不进入运行证据。数据默认保留 30 天、最多 180 天，主存储到期后 24 小时内删除，备份和异地副本 7 天内删除。

## 14. P0 不做与后续扩展

P0 不做 Web 资产编辑、Git 写回、临时运行参数、用户配置重试、自由 Shell、性能压测、邮件/企业微信通知、步骤 when、ES 检索和流程写库。

P0 的 Scenario 不声明外部 `inputs`，`inputs` 根仅属于 Flow、ApiContract 和 Page route 等当前可调用资产作用域。所有运行入口仍须通过统一调用上下文和输入绑定边界进入快照；P0 的调用输入绑定及已解析 Scenario 输入固定为空，任何非空绑定都应在编译前拒绝。后续若开放 Scenario 输入，必须通过新的版本化 DSL 能力增加类型化声明，并在快照形成前完成绑定和校验，不能让 Worker 直接读取 Web、定时任务、Suite、API 或 MCP 的原始参数。

后续扩展必须保持兼容边界：

- when 需要重新定义跳过传播、可选输出、cleanup 和报告语义。
- XPath 必须通过新 DSL 版本增加独立定位策略、受限语法、唯一匹配与兼容性测试，不能改变既有 `css` 的解释。
- 图片脱敏和截图专属权限后续通过独立制品治理能力增加；P0 原始截图不参与结构化数据的 masked/revealable/raw 分级。
- Adapter 只随受控平台部署安装并通过稳定 ID、版本、协议和内容摘要进入 Worker 能力声明；P0 不从 Web、YAML 或资产 Git 仓库加载执行代码。
- ES 需要通过新的版本化 `es.search` 动作增加结构化查询、索引绑定、有界结果和审计边界，不能把底层客户端语法直接暴露为 P0 能力。
- 自动化写库必须通过已发布 SqlContract 和独立 sql.execute，不能放宽 sql.query。
- 操作符按版本化注册表扩展，不能改变已发布语义。
- MCP 只在控制面 API、鉴权、队列、Worker 和报告访问控制成熟后接入。

## 15. 批准结果与后续出口

本文件中的资产外壳、七类资产边界、值节点和类型、DataSet 共享、Step 认证、等待/重放、跨系统 Scenario、SQL 只读、报告与安全约束已整体批准；ES 已由后续访谈明确移出 P0。下一阶段进入控制面、Engine 与 Worker 的发布修订、运行快照、执行计划和结果协议设计，不直接进入实现。
