# S1：发布修订、统一调用、运行快照与编译计划

状态：已批准。

批准记录：用户于 2026-09-24 确认本规格整体批准；第 7 节技术契约决定属于本次批准范围。

- 《2026-09-23-总体技术架构与跨组件协议》§§1-3.4、§§5-8，尤其是发布不可变、快照绑定、同步编译、Plan 由 Control 持久化和分层版本兼容约束。
- 《产品需求规格》§5.1、§§6.3-6.5、§§8-9、§§11。
- 《2026-09-21-最小领域专用语言设计》§§2-3、§§8、§§12-15。
- `docs/领域模型/领域术语.md` 中“已发布修订”“运行快照”“可执行调用”“已解析 Scenario 输入”“资产 Schema 版本”等定义。
- 相关 ADR：0003、0005、0012、0034、0036。

上述来源是语义权威；本规格的字段名和 HTTP 形状只在本草案获批后成为技术契约。

## 2. 依赖与不变量

```text
SynchronizedCommit
  -> WholeRootValidation
  -> PublishedRevision (immutable)
  -> ExecutableInvocation
  -> InputBinder (P0: empty external binding)
  -> RunSnapshot (immutable)
  -> CompileRequest
  -> Engine CompileResult
  -> Control validates and persists Plan (immutable)
  -> queueable Run
```

- 发布修订是完整资产根，不是单资产或临时依赖闭包；远程 Git 后续移动或删除不能影响既有修订。
- Snapshot 必须携带完整运行解释所需的冻结内容或可验证的内容寻址引用；Compiler/Worker 不得读取活动分支或可变配置补全语义。
- P0 的 `ResolvedScenarioInputs` 是显式空集合；任何非空 `InvocationInputBinding` 在 Snapshot 形成前拒绝。
- Plan 的动作、租约键、cleanup 顺序和能力需求必须可从同一 Snapshot 确定性重算；Control 不得接受只给摘要而没有可验证正文的 Plan。

## 3. 字段与摘要契约

以下字段是最小协作集合。标记为“必需”的字段属于 P0 协作契约；可选字段只有在 `optionalFeatures` 明确声明后才允许出现。

### 3.1 PublishedRevision

| 字段 | 状态 | 约束 |
| --- | --- | --- |
| `revisionRef` | 必需 | 平台生成的 UUIDv7 不透明不可变引用；不把任意 Git SHA 或内容摘要当作业务主键。 |
| `projectRef` | 必需 | 所属测试项目。 |
| `sourceCommit` | 必需 | 同步时固定的 Git commit 标识。 |
| `assetRootRef` | 必需 | 已校验资产根边界。 |
| `contentDigest` | 必需 | 对按相对路径排序的 `contentManifest` 进行 RFC 8785 JCS 规范化后计算 SHA-256；覆盖整根发布内容。 |
| `contentManifest` | 必需 | 记录文件相对路径、原始字节 SHA-256、字节长度和资产身份，用于根摘要、恢复集和差异显示；不得成为第二语义来源。 |
| `dslVersions` | 必需 | 发布内容实际使用的 `apiVersion` 集合。 |
| `operatorVersions` | 必需 | 资产引用的转换/断言操作符及版本。 |
| `validationSummary` | 必需 | 全根校验结果、校验器契约版本和非敏感摘要。失败修订不可发布。 |
| `publishedAt`/`publishedBy` | 必需 | 发布审计关联；`publishedBy` 是不可变 `userId`。 |

发布、历史激活和活动修订切换必须是 Control 内单事务：内容持久化、摘要、验证结果和活动引用要么一起可见，要么都不可见。历史激活不得改变旧修订正文。

### 3.2 ExecutableInvocation

| 字段 | 状态 | 约束 |
| --- | --- | --- |
| `invocationId` | 必需 | 调用方生成；手动调用按 `userId + invocationId` 在 24 小时窗口幂等。 |
| `invocationKind` | 必需 | `manual`、`schedule`；为后续 API/MCP 保留扩展位，但 P0 不开放新入口。 |
| `callerRef` | 必需 | `userId` 或调度器/服务身份；不能把调度器伪装成创建者。 |
| `projectRef` | 必需 | 项目边界。 |
| `entryKind`/`entryRef` | 必需 | `Scenario`、`Suite` 或 `ApiCheckSet` 及其稳定资产 ID。 |
| `environmentRef` | 必需 | 运行环境；不允许在 Worker 端再解析活动配置。 |
| `invocationInputBinding` | 必需 | P0 固定为空对象/空列表，非空拒绝。 |
| `policySelection` | 必需 | 任务失败策略、队列等待上限、报告访问模式、通知选择等入口可选策略的规范化值。 |
| `scheduleRef`/`scheduledFireTime` | 条件必需 | 定时调用使用 `scheduleRef + scheduledFireTime` 幂等；时间同时保存 UTC、本地计划时间、IANA 时区和规则版本。 |
| `requestDigest` | 必需 | 对规范化调用正文按 RFC 8785 JCS 编码后计算 SHA-256，用于幂等冲突判定。 |
| `requestedAt` | 必需 | 服务端接收时间；调度触发另保存计划时间。 |

相同幂等键和相同 `requestDigest` 返回原 Run；相同幂等键不同摘要返回结构化幂等冲突，不创建 Snapshot、队列项或外部动作。

### 3.3 Run Snapshot

| 字段 | 状态 | 约束 |
| --- | --- | --- |
| `snapshotRef`/`snapshotDigest` | 必需 | `snapshotRef` 是平台生成的 UUIDv7 不透明 ID；`snapshotDigest` 是正文 RFC 8785 JCS + SHA-256 完整性摘要。Worker 和 Engine 必须校验摘要。 |
| `runId` | 必需 | Control 生成的持久 Run 标识。 |
| `publishedRevisionRef`/`contentDigest` | 必需 | 固定发布修订及内容摘要。 |
| `assetClosure` | 必需 | 保存入口资产及完整引用闭包的不可变发布对象引用、closure manifest 和逐项摘要，不重复复制整根正文；不得在运行期间回读 Git。 |
| `dslVersions`/`operatorVersions` | 必需 | 解释语义版本。 |
| `environmentBindingVersions` | 必需 | Target System、Managed Connection 和环境解析版本。 |
| `adapterRequirements`/`workerCapabilityRequirements` | 必需 | Adapter ID/版本/协议/摘要及 Worker 能力要求。 |
| `resolvedActors` | 必需 | 每个 `actorRef` 的目标系统、通道、Test Identity、认证 Profile 版本和凭据版本引用；不含明文。 |
| `resolvedScenarioInputs` | 必需 | P0 固定为空。 |
| `runPolicy` | 必需 | 排队、动作、Run、cleanup、制品配额等实际生效限制。 |
| `reportAccessPolicy` | 必需 | `masked`/`revealable`/`raw` 及脱敏策略版本。 |
| `notificationSelection` | 必需 | `channelRef`、配置版本、接收人和通知策略；不含密钥。 |
| `createdAt`/`createdBy` | 必需 | 快照事实和调用主体。 |

Snapshot 一旦持久化不得原地更新。Snapshot 引用的发布对象必须与 Snapshot 共同保留、备份和恢复；引用缺失属于存储损坏，不得回读 Git 补全。普通凭据轮换不改 Snapshot；紧急撤销在排队前阻止使用，在运行中下一次取得/刷新时失败。

### 3.4 CompileRequest 与 Plan

使用内部版本化 HTTP/JSON 接口，逻辑操作如下。各引用字段均使用平台生成的 UUIDv7 不透明 ID：

`Control -> Engine: CompileRequest`

```json
{
  "protocolVersion": "<major>.<minor>",
  "compileRequestId": "<opaque-id>",
  "snapshotRef": "<ref>",
  "snapshotDigest": "sha256:<digest>",
  "compilerContractVersion": "<version>",
  "requestedPlanFormatVersion": "<version>",
  "requiredCapabilities": {
    "dsl": [],
    "operators": [],
    "adapters": []
  }
}
```

`Engine -> Control: CompileResult`

```json
{
  "protocolVersion": "<major>.<minor>",
  "compileRequestId": "<opaque-id>",
  "snapshotRef": "<ref>",
  "snapshotDigest": "sha256:<digest>",
  "planFormatVersion": "<version>",
  "compilerVersion": "<version>",
  "planDigest": "sha256:<digest>",
  "plan": { "...": "deterministic plan body" },
  "leaseRequirements": [],
  "capabilityRequirements": [],
  "summary": {
    "actionCount": 0,
    "attemptBudget": 0,
    "leaseCount": 0,
    "cleanupCount": 0
  }
}
```

Control 必须检查 `snapshotRef`/digest、Plan digest、计划格式、能力清单、动作/资源上限和租约键后才分配 UUIDv7 `planRef` 并持久化正文。Plan 正文按 RFC 8785 JCS 规范化后计算 SHA-256。Engine 不持有 Plan 存储权威；Worker 只按 `planRef` 从 Control 领取，并在任务领取后取得完整不可变 Plan。凭据和其他敏感动作材料不进入 Plan，仍按 Step/Attempt 最小发放。

`summary` 只用于快速展示和验收断言，不能替代正文或重新解释动作。动作顺序、Flow/Suite 展开、cleanup、wait/authRefresh 尝试和身份租约键必须在正文中可验证。

## 4. 版本与兼容矩阵

| 层 | 必须检查 | 兼容规则 | 不兼容结果 |
| --- | --- | --- | --- |
| HTTP/JSON 协议 | `protocolVersion`、`requiredFeatures`、`optionalFeatures` | 使用整数 `major.minor`；主版本相同，次版本只可增加已声明可选字段/能力 | 编译请求拒绝；不入队 |
| Snapshot 格式 | `snapshotFormatVersion`、摘要 | 主版本相同；缺失必需字段或未知必需语义拒绝 | `rejected + asset/platform`，按阶段记录 |
| DSL | 每个 `apiVersion` | 资产 Schema 语义不能静默改变；不支持版本在发布/编译前拒绝 | 发布失败或编译拒绝 |
| Plan | `planFormatVersion`、`planDigest` | Worker 必须支持完整 Plan 语义；只允许声明的可选扩展 | 不领取/执行 |
| 操作符 | 名称+版本+语义摘要 | 注册表版本和输入/输出语义必须匹配 | 发布/编译/领取前拒绝 |
| Adapter | 稳定 ID+版本+协议+内容摘要 | Worker 能力必须覆盖所需版本 | 运行前 `rejected + configuration/policy` |
| Worker 能力 | 能力 ID、版本、槽位 | 只选择能力覆盖且未撤销的 Worker | 保持 `queued` 或队列超时 |

所有协议和格式版本均使用整数 `major.minor`；构建版本单独记录，不参与兼容判断。次版本“可选扩展”必须进入显式 `optionalFeatures`，必需扩展进入 `requiredFeatures`；未知必需字段、能力、操作符或状态不得忽略。升级前要逐项检查所有排队 Snapshot。

## 5. 异常路径与状态约束

- Git 内容、引用、全根 Schema 或能力校验失败：不生成 PublishedRevision。
- 发布/活动切换并发冲突：按配置版本返回冲突，不覆盖他人修改。
- Snapshot 形成前发现项目归档、环境绑定缺失、凭据版本紧急撤销或非空输入绑定：创建 `rejected` Run 事实但不入队。
- Engine 超时、不可用、摘要不匹配、计划超限或能力不足：保存 `rejected + platform/asset/policy` 的稳定错误，不产生可领取任务。
- Control 重试同一 CompileRequest 时必须使用相同 Snapshot 摘要；若 Engine 返回不同 Plan 摘要，Control 记录协议故障并拒绝持久化，不选择“最新结果”。
- 任一外部动作未开始前的编译/排队失败不产生 Attempt；Attempt 规则见 S2。

## 6. 验收方法

- 固定同一发布内容、同一 Snapshot 和同一 Compiler 契约，多次编译得到字节等价 Plan 与相同 `planDigest`；不同活动修订不能改变已形成 Snapshot 的编译输入。
- Git 分支移动、强推或远端不可用后，已发布修订和 Snapshot 仍可读取、校验和编译。
- 手动重复提交相同 `userId + invocationId + requestDigest` 只得到同一 Run；同 ID 不同摘要返回幂等冲突。
- P0 任意非空 Scenario 外部输入在 Snapshot 前拒绝，Worker/Compiler 不接收原始入口参数。
- 缺少必需 DSL/操作符/Adapter/Worker 能力、未知必需字段或主版本不一致均在入队前拒绝；已声明可选次版本扩展可被安全忽略。
- Snapshot/Plan 内容摘要被篡改、Plan 摘要与正文不符或引用不存在时，Control/Worker 拒绝并记录协议事件。
- 验收记录发布、激活、回退、编译、拒绝和幂等冲突的审计链，且不含凭据明文。

## 7. 已确认的技术契约决定与验证项

用户于 2026-09-24 确认：

1. JSON 正文统一使用 RFC 8785 JCS 规范化并计算 SHA-256；发布根摘要基于排序 manifest，manifest 保存每个文件的原始字节摘要和长度。
2. `revisionRef`、`snapshotRef`、`planRef`、`compileRequestId` 使用平台生成的 UUIDv7 不透明 ID；摘要只用于完整性校验，不作为业务主键。
3. Snapshot 保存不可变发布对象引用、closure manifest 和逐项摘要，不重复复制整根正文；引用对象与 Snapshot 共同保留、备份和恢复。
4. Worker 在任务领取后取得完整不可变 Plan；敏感材料按 Step/Attempt 最小发放。
5. 版本字段使用整数 `major.minor`，配合 `requiredFeatures`/`optionalFeatures`；构建版本单独记录。

CompileRequest 的同步预算、HTTP 超时和安全重试次数需通过参考单机拓扑 prototype 校准，以满足手动 Run 创建 p95 不超过 3 秒。重复 `compileRequestId` 只能在相同 Snapshot 摘要和相同请求摘要下返回原结果；不同内容复用 ID 返回幂等冲突。实测参数不得改变编译前置、不入队拒绝、确定性 Plan 或不自动重放语义。
